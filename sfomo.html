Pipeline

6 AI Agents, Running in Sequence

Each cycle runs all six agents in a deterministic LangGraph pipeline. GPT-4o reasons at the strategy and learning layers.

1

Market Intelligence

Fetches OHLCV candles, order books, funding rates, sentiment scores, and on-chain metrics. LLM classifies the current market regime.

2

Strategy

Runs all 5 strategies in parallel, applies regime-based weight adjustments, then LLM filters to high-conviction signals only. Reasoning field excluded from filter prompt to prevent injection.

3

Risk Management

Fixed-fractional position sizing by confidence, VaR check, drawdown guard, kill switch verification. Fails closed on Redis errors.

4

Execution

Live balance check → TWAP for large orders (with kill switch re-check between slices and random interval jitter) → market order for small. UUID clientOrderId on every order. Liquidity check blocks if insufficient depth.

5

Portfolio Manager

Updates equity snapshot, persists peak for drawdown calculation, compounding reinvestment using cycle-delta PnL (not cumulative), rebalance detection.

6

Learning

LLM evaluates the completed cycle, adjusts strategy weights (±5% cap per cycle), records regime history, stores cycle summary in Qdrant vector DB for future reference.

Strategies

5 Battle-Tested Approaches

Weights are dynamically adjusted per market regime. The Learning agent fine-tunes them each cycle based on performance.

📈

Trend Following

EMA crossover with RSI filter. Captures sustained directional moves in bull and bear markets. Default weight 30%.

30% base weight
🚀

Momentum Breakout

Donchian channel breakouts confirmed by volume surge. Targets explosive moves at structural highs/lows. Default weight 25%.

25% base weight
↩

Mean Reversion

Bollinger Bands (sample std) + RSI extremes. Buys oversold, sells overbought in ranging conditions. Default weight 20%.

20% base weight
⚡

Volatility Arb

Fades funding rate extremes on perpetuals. Profits from mean-reversion of funding after extreme positive/negative readings. Default weight 15%.

15% base weight
🔄

Portfolio Rotation

Risk-adjusted momentum ranking across all trading pairs. Rotates capital toward the strongest performers. Default weight 10%.

10% base weight
🧠

Regime Adaptation

Weights are multiplied by regime-specific adjustments each cycle. Bull trend boosts trend/momentum; ranging boosts mean reversion. Learning agent further refines.

Dynamic
Risk Management

Safety First, Always

Multiple independent layers of protection. Paper trading by default. Every decision is logged.

Position-Level Controls

Applied before every order is sent

🛡

Fixed-Fractional Sizing

Risk per trade = equity × risk_pct × confidence. Maximum 0.5% equity at risk. Position capped at 20% of equity regardless.

📊

Minimum Stop Distance Guard

Stop loss must be at least 0.01% from entry. Prevents epsilon-tiny stops from inflating position sizes via IEEE-754 arithmetic.

✓

Live Balance Check

Queries exchange balance before every order. Skips the order if available free balance is insufficient, even in concurrent scenarios.

⚖

Minimum 1.5× R:R Ratio

Every signal validated for risk/reward before approval. Signals with R:R below 1.5 are rejected regardless of confidence.

Portfolio-Level Controls

Applied every cycle, persisted in Redis

🔴

Kill Switch (Redis-Persistent)

Triggers at configured max drawdown (default 15%). Survives restarts and is shared across all workers. Requires ADMIN_KEY to reset — separate from API_KEY.

🔒

Global Cycle Mutex

asyncio.Semaphore(1) prevents concurrent cycles from racing on portfolio state, exchange balances, and kill switch transitions.

📋

Append-Only Audit Log

audit_logs table has REVOKE UPDATE, DELETE enforced at the database level. Every order fill and failure is permanently recorded.

📄

Fail-Closed on Redis Errors

If Redis is unreachable, the cycle halts with skip_execution=True. Never trades when the kill switch state is unknown.

Deployment

Live in Minutes on Railway

Monorepo with two services — backend (Python) and frontend (Node). Each needs its own root directory configured.

Setup Steps

  1. Create Railway project

    New project → Deploy from GitHub → select this repo

  2. Add Backend service

    Settings → Root Directory → backend → add PostgreSQL and Redis plugins

  3. Add Frontend service

    Same repo → Settings → Root Directory → frontend

  4. Set environment variables

    Backend: SECRET_KEY, API_KEY, ADMIN_KEY, OPENAI_API_KEY, exchange credentials, CORS_ORIGINS

  5. Generate secure keys

    All three keys must be unique and at least 32 characters

  6. Deploy & open dashboard

    Railway builds both Dockerfiles automatically. Frontend URL opens the trading dashboard.

Generate Keys

# Generate all three keys independently
python -c "import secrets; print(secrets.token_hex(32))"
# Run three times → SECRET_KEY, API_KEY, ADMIN_KEY
